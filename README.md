# Лабораторная работа НТИ: видео, речь и биосигналы

[Публичный репозиторий](https://github.com/akabynda/nti-multimodal-lab)

Локальное приложение для сопоставления речи с правдивыми письменными историями, анализа ЭКГ, дыхания, лицевой rPPG и видимой кинематики. Интерфейс содержит пять синхронных зон: время, стенограмму с эталоном, сигналы, одно видео и аналитический дашборд.

Письменные истории служат правдивым эталоном эксперимента. Система сопоставляет с ними устные ответы, показывает совпадения и расхождения с цитатами, вопросами и таймкодами.

## Быстрый запуск в подготовленной папке Windows

Запустите `start.cmd`, затем откройте http://127.0.0.1:8765 . На компьютере, где выполнялась обработка, окружение `.venv` и результаты уже подготовлены.

```powershell
cd C:\path\to\nti-lab
.\.venv\Scripts\python.exe -m uvicorn nti_lab.app:app --host 127.0.0.1 --port 8765
```

Интерфейс работает локально. Для новой папки данных задайте `NTI_DATA_ROOT`, для другого расположения результатов — `NTI_PROJECT_ROOT`. Эти переменные не содержат секретов.

## Установка с нуля

Поддерживается Python 3.12 на Windows и Linux; macOS использует CPU. Для браузерного просмотра достаточно 4 ГБ памяти. Для обработки всех записей рекомендуется 16–32 ГБ RAM и свободное место под исходные видео, модели и результаты. GPU необязателен. Для CUDA ASR нужны совместимые CUDA 12 и cuDNN 9; видеотрекинг работает на CPU.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install -e . --no-deps
```

В Linux/macOS замените путь к интерпретатору на `.venv/bin/python`. Точные версии фактически проверенного Windows-окружения записаны в `requirements-windows-lock.txt`. Основной `requirements.txt` допускает совместимые платформенные сборки; Docker отдельно проверяет Linux.

## Данные и порядок обработки

Разместите исходники по инструкции `data/README.md`. Медиа и персональные результаты не входят в публичный код.

```powershell
.\.venv\Scripts\python.exe scripts/analyze_bio.py --help
.\.venv\Scripts\python.exe -m nti_lab.audio --help
.\.venv\Scripts\python.exe scripts/analyze_video.py --input ../1_30 --workers 4
.\.venv\Scripts\python.exe scripts/make_proxies.py --input ../1_30
.\.venv\Scripts\python.exe scripts/analyze_research.py
.\.venv\Scripts\python.exe scripts/estimate_sync.py --help
```

Команды биосигналов, ASR и диаризации с полными параметрами находятся в `docs/bioradio_format.md` и `docs/audio_method.md`. Программы читают исходные файлы и записывают производные результаты в `outputs/`. Скачивание моделей производится с официальных хранилищ; хеши видеомоделей записываются в результат.

Для ASR сначала можно выполнить быстрый проход всех записей, затем акустику и нейросетевое разделение голосов. Промежуточные результаты сохраняются по участникам. Превью создаются в `.partial.mp4` и переименовываются после успешного завершения FFmpeg.

### Автоматические кандидаты синхронизации

После обработки биосигналов, речи и видео выполните:

```powershell
.\.venv\Scripts\python.exe scripts/estimate_sync.py
```

Для одной записи добавьте её идентификатор, например, `--recording 00001_Participant01`. Программа использует подтверждённый порядок включения: БиоРадио начинается раньше видео и заканчивается позже. Поэтому опережение БиоРадио находится между нулём и разницей длительностей. Смещение для интерфейса имеет обратный знак: `video_time = bio_time − lead_s`.

Начальный и конечный спокойные участки определяются раздельно по инструкциям закрыть глаза в ASR; относительное раскрытие глаз по видеоточкам служит дополнительным признаком. Для сопоставления с rPPG R-пики ЭКГ преобразуются в сглаженную последовательность импульсов; оба сигнала фильтруются в полосе 0,65–3 Гц. Сравниваются абсолютные корреляции, конкурирующие максимумы и согласие двух участков. Временной ноль медиа определяется первым декодированным кадром и аудиофреймом, а не метаданными начала видеопотока.

Статус `supported_unverified` означает согласованный кандидат, `ambiguous_unverified` — неоднозначный. Оба требуют проверки. Масштаб времени остаётся равным 1: дрейф без независимых опорных меток не оценивается. Задержка пульсовой волны смешивается со смещением часов; диапазон 0,08–0,45 с используется лишь как допущение для анализа чувствительности. Сохранённый интервал не является статистическим доверительным интервалом и не гарантирует физиологическую границу.

В `outputs/sync/` сохраняются подробные JSON, `summary.csv`, `comparisons.csv` и `aggregate_summary.png`. Сравнения пульса ЭКГ/rPPG и дыхательного пояса/движения плеч остаются предварительными при неподтверждённом смещении. Количество пар относится к перекрывающимся окнам, а не к независимым наблюдениям.

## Работа с интерфейсом

1. Выберите участника. Кнопки «−1 кадр» и «+1 кадр» используют частоту исходного видео.
2. Выберите письменную историю. Под ней показаны содержательные сопоставления с расшифровкой; кнопка с таймкодом переводит к эпизоду.
3. Назначьте роли голосов после прослушивания. Автоматический кластер ещё не означает подтверждённую роль.
4. Проверьте синхронизацию. Общее время вычисляется как `offset_s + scale × source_time`. БиоРадио включалось раньше видео и выключалось позже. Начальный и конечный спокойный фон проверяются раздельно.
5. Добавьте интервалы базы, вопроса, ответа, темы, правды или лжи. Для последнего укажите основание и отметьте экспертную проверку. Разметка хранится в `data/private/annotations/`.

## Архитектура

`biosignals.py` читает BCRX (ZIP → raw DEFLATE → float32), сохраняет реальные пропуски и извлекает ЭКГ, RIP и GSR. RR-фильтрация предшествует расчёту ВСР. Окно ВСР 120 с, шаг 5 с.

`vision.py` использует MediaPipe Pose для выделения области головы, Face Landmarker для лба и щёк, POS для rPPG и видимые точки тела для двумерной кинематики. Скрытые конечности остаются пропущенными. Спектральные оценки пульса и дыхательного движения сопровождаются показателями качества.

`audio.py` использует локальную faster-whisper large-v3, FFmpeg, временные метки слов, Praat и спектральные признаки. `speakers.py` разделяет голоса через WeSpeaker/Sherpa ONNX. Исходные и отредактированные расшифровки сохраняются отдельно.

`research.py` ведёт источники и их хеши, сопоставляет истории и стенограммы, проверяет доступность меток для исследования. Содержательная сверка сохранена отдельно от автоматического лексического поиска. Модели используют разделение по участникам, а не случайное перемешивание перекрывающихся окон.

`alignment.py` оценивает допустимый диапазон смещения и проверяет кандидаты на спокойных участках. `sync.py` реализует линейные часы по одной или нескольким ручным опорным меткам.

`app.py` — FastAPI с локальными файлами, JSON API и простым браузерным клиентом без внешних CDN. В коде интерфейса используется `textContent`, чтобы стенограммы не исполнялись как HTML.

## Ограничения именно предоставленного набора

- В восьми записях сохранены ЭКГ, RIP и GSR по 1000 Гц. Девятая содержит семь каналов по 250 Гц, включая контактный ФПГ; для неё рассчитаны PRV и сравнение с ЭКГ на общих часах БиоРадио.
- Видеоракурс один.
- Записи БОС и видео имеют разные моменты запуска/остановки. До проверки смещения сравнения модальностей предварительны.
- GSR содержит плоские участки и значения вне рабочего диапазона; они отмечены при контроле качества.
- ULF не оценивается по 120 секундам. VLF и LF/HF трактуются как исследовательские показатели с ограничениями.
- Профили из XLSX используют иную типологию, чем классические четыре темперамента. Автоматическое преобразование между ними не выполняется.
- Устные ответы сопоставляются с письменными эталонами вместе с контекстом вопроса.

## Docker

```powershell
docker compose up --build -d
docker compose logs --tail 50
docker compose down
```

Сервис привязан к `127.0.0.1:8765`. Исходники монтируются только для чтения. `outputs`, локальная разметка и модели вынесены в тома. Если локальный Python-сервис уже использует порт, сначала остановите его или измените внешний порт в `docker-compose.yml`.

## Проверки и воспроизводимость

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/audit_audio.py
docker build -t nti-lab .
docker run --rm nti-lab python -m pytest -q
```

Тесты проверяют бинарный формат, известную частоту пульса, спектральные ограничения, временные часы, речь/тишину, защиту от утечки участников между train/test, разметку API. Проверки на искусственных сигналах — тесты алгоритмов, не результаты на людях. GitHub Actions запускает тесты и сборку контейнера. Фактическая локальная проверка описывается в `docs/validation.md`.

После расчёта всех модальностей выполните `python scripts/audit_project.py`, затем `python scripts/build_report.py`. Отчёт создаётся в `outputs/report/Отчет НТИ.pdf`; личные данные остаются локальными. Краткий сценарий защиты и ответы на методические вопросы находятся в `docs/defense.md`.

`configs/pipeline.json` фиксирует параметры проведённого расчёта. Это описательный манифест; изменение файла само по себе не меняет параметры программ. Доступные параметры запуска перечислены в `--help` соответствующего скрипта.

## Структура

```text
configs/       параметры обработки
data/          инструкция; private/ исключена из Git
src/nti_lab/   обработка, API и интерфейс
scripts/       команды пакетной обработки
tests/         численные и интеграционные проверки
notebooks/     воспроизводимый исследовательский анализ
docs/          методика и проверки
outputs/       локальные результаты, не публикуются
```

Исходные видео, биосигналы, истории, персональные профили, модели и DLL исключены из Git и Docker build context. Публикуется только программный проект и общая методика.
