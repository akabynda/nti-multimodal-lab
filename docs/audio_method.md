# Аудиоаналитика

Модуль `nti_lab.audio` обрабатывает исходную аудиодорожку каждого MTS полностью. Используется моно, 16 кГц; исходный файл не изменяется. Отсчёт времени начинается с первого декодированного аудиосэмпла. Сдвиг относительно контактных датчиков задаётся отдельно в интерфейсе синхронизации.

## Запуск

```powershell
python -m nti_lab.audio --input ../1_30 --output outputs/audio --skip-existing
```

Чтобы получить все стенограммы до окончания акустических вычислений, можно запустить две команды в отдельных терминалах:

```powershell
python -m nti_lab.audio --input ../1_30 --skip-existing --asr-only
python -m nti_lab.audio --input ../1_30 --skip-existing --features-only --wait-for-asr
```

Вторая команда ожидает готовую стенограмму каждой записи и использует CPU, первая выполняет ASR на GPU.

Первый проход использовал `faster-whisper-large-v3-turbo`, CTranslate2, `int8_float16`, язык `ru`, beam size 5, batch size 4. Полный повторный проход использует **Whisper large-v3**, `int8_float16`, beam size 10 и batch size 4:

```powershell
python -m nti_lab.audio --input ../1_30 --output outputs/audio-large-v3 --model models/faster-whisper-large-v3 --beam-size 10 --batch-size 4 --asr-only --skip-existing
```

Фактическая модель, SHA256 весов и настройки декодирования записываются в JSON. Исходные ответы модели до разбиения реплик сохранены как `.raw.json`. Предыдущий проход остаётся отдельной версией для сравнения. Для CPU:

```powershell
python -m nti_lab.audio --input ../1_30 --model turbo --device cpu --compute-type int8 --batch-size 4 --skip-existing
```

Для GPU требуются CUDA 12 / cuBLAS и cuDNN 9. В текущем Windows-окружении используется существующий CUDA 12.1 и cuDNN 9.1.1.17, установленный в локальный каталог проекта:

```powershell
python -m pip install --target vendor --no-deps nvidia-cudnn-cu12==9.1.1.17
```

Модуль добавляет `vendor/nvidia/cudnn/bin` и `$env:CUDA_PATH/bin` только в окружение своего процесса. Системные переменные не меняются. В Linux следует использовать подходящий образ CUDA либо официальные инструкции библиотек. Дополнительная акустическая зависимость: `praat-parselmouth==0.4.6`.

## Результаты

Для каждой записи `00001_Participant01` формируются:

- `outputs/audio/00001_Participant01.segments.json` — стенограмма, тайминги слов, реплики, предварительные спикеры, интервалы речи и кандидаты «вопрос — ответ»;
- одноимённый `.txt` — читаемая стенограмма с таймкодами;
- `.features.csv` — акустические окна 5 с с шагом 1 с;
- `.summary.json` — объём обработки и ограничения.

`recording_id` — полное имя без расширения, `participant_id` — часть после первого подчёркивания. Время `start/end` реплик и слов задано в секундах от начала аудиодорожки. `time_s` в CSV — середина окна.

Автоматические чанки ASR дополнительно разбиваются по пунктуации, межсловной паузе ≥ 650 мс либо достижении 15 с. Это предварительное разбиение реплик, а не подтверждённая разметка смены спикера. Поле `source_chunk_id` связывает реплику с исходным чанком распознавания.

## Признаки и интерпретация

F0 оценивается автокорреляционным методом Praat в диапазоне 60–500 Гц. F1–F3 — Burg-formants с верхней частотой 5500 Гц, только в кадрах с обнаруженной основной частотой. Энергия выражена в dBFS, то есть относительно цифровой полной шкалы, а не в калиброванных dB SPL. Спектральный центр и наклон спектра описывают записанный сигнал; наклон рассчитан на 100–4000 Гц в dB/октаву. Доля клиппинга показывает возможное ограничение амплитуды. Признаки относятся к смеси записанных голосов в каждом окне.

Детектор Silero VAD задаёт интервалы речи. Длительность речи и пауз вычисляется по объединению интервалов, поэтому пересечения не учитываются дважды. Число слогов оценивается числом гласных в распознанном тексте; полноценная фонетическая транскрипция не выполняется. WPM и слоги/с зависят от ошибок ASR и границ реплик.

## Диаризация и ручная проверка

В подготовленных результатах применяется WeSpeaker ResNet34 ONNX: нейросетевой вектор голоса, нормализация до единичной длины и KMeans с двумя кластерами, seed 42 и 30 инициализациями. Каждая реплика длиной от 0,7 с представлена центральным фрагментом не длиннее 6 с. Более короткие реплики остаются `unknown`. Модель обучалась на англоязычном VoxCeleb и применена к русской речи без размеченного теста диаризации; перенос не считается валидированным.

Для воспроизведения:

```powershell
python -m pip install sherpa-onnx==1.13.8
python -c "from huggingface_hub import hf_hub_download; hf_hub_download('csukuangfj/speaker-embedding-models','wespeaker_en_voxceleb_resnet34.onnx',local_dir='models/speaker')"
python -m nti_lab.speakers --input ../1_30 --wait-for-acoustics --workers 3
```

SHA256 модели: `5ef208a9da1453335308a6b6f4e6dfbd7e183a38b604de0a57664f45d257fe94`. Обработка локальная; векторы голоса не записываются в выходные файлы и никуда не отправляются. При наличии модели основной `nti_lab.audio` также автоматически использует её. Если модели нет, резервный вариант — статистики MFCC каждой реплики, стандартизация, KMeans с двумя кластерами и seed 42; метод явно записан в JSON.

Кластеры обозначены A/B. Подтверждённые роли **не назначаются автоматически**. Поле `speaker_role_candidate` содержит предварительную роль по частоте вопросов в тексте, если разница между кластерами ≥ 0,15 и каждый кластер содержит не менее 10 реплик и 10% распределённых реплик. Иначе роли остаются неопределёнными, а дисбаланс помечается в `cluster_balance_check`. `speaker_role` остаётся `unconfirmed` до ручной разметки. Разные акустические условия могут разделить одного человека на два кластера или объединить голоса; одновременная речь и смена говорящего внутри реплики не разделяются. Silhouette score характеризует геометрию кластеров, а не точность определения человека. `speaker_similarity_margin` — разница косинусного сходства с центрами кластеров, не вероятность правильной классификации.

Ручные поправки сохраняются в `data/private/annotations/speakers/<recording_id>.json`:

```json
{
  "intervals": [
    {"start": 0, "end": 8.1, "speaker_id": "A", "speaker_role": "interviewer"},
    {"start": 8.1, "end": 12.5, "speaker_id": "B", "speaker_role": "respondent"}
  ]
}
```

Числа в примере условные, это не разметка реальной записи. Поправка применяется к репликам, середина которых попадает в интервал. После повторного запуска `--skip-existing` ASR не выполняется заново, а акустика и разметка пересчитываются.

Кандидат вопроса обнаруживается по вопросительному знаку, следующий сегмент считается кандидатом ответа. Поэтому пары, длительность ответа, паузы и латентность требуют экспертного подтверждения. Они не используются как достоверные метки ответа до проверки. Для реального многорепликового ответа следует объединить соответствующие сегменты в экспертной разметке.

Ни один акустический признак и ни одна автоматическая реплика сами по себе не устанавливают ложь, скрываемую информацию или психоэмоциональное состояние. Модуль не выдаёт вероятность лжи.

## Проверки

`tests/test_audio.py` проверяет основной тон на известном гармоническом сигнале 180 Гц, отсутствие обнаруженной частоты при цифровой тишине, корректность объединения перекрывающихся интервалов речи и различие между латентностью ответа и паузами внутри ответа.

ASR-тайминги на границе файла могут выходить за длительность записи. Такие значения ограничены доступным диапазоном; исходные значения сохранены в `raw_model_start/end`, флаг — `timing_clipped_to_recording`. Это ограничение времени, а не исправление распознанного текста.

## Проверка и исправление текста

`scripts/review_audio.py` сравнивает старое и новое распознавание по времени и формирует `transcript_comparison.json`. Низкая вероятность слова, различия отрицаний, повторы и большие расхождения служат поводом для проверки, а не доказательством ошибки. Письменные истории в этот процесс не загружаются.

Неясные фрагменты повторно декодируются из исходной аудиодорожки скриптом `scripts/redecode_audio_review.py`: полная large-v3, beam size 10 и 1, температура 0, без VAD, начальной подсказки и обусловливания предыдущим текстом. Контекст, хеш декодированного звука, хеш исходной стенограммы и оба результата сохраняются в `outputs/audio-large-v3/rechecks/`. Это повторное автоматическое распознавание, а не подтверждённое человеком прослушивание.

Исправления вносятся только через явный журнал: исходная строка, новая строка, причина и хеш файла повторного распознавания. Неустранённая неоднозначность помечается для прослушивания. Исходные `.segments.json` не перезаписываются; читаемые исправленные версии находятся в `reviewed/`, сводка — `validation_summary.json`. Сохранённые тайминги слов относятся к исходному ASR; при редакторской замене текста это явно отмечено в `word_alignment_status`. Если границы уточнены по повторному ASR, исходные слова и время также сохранены, а уточнённые границы помечены отдельно. Пропущенные ответы добавляются отдельными сегментами с временными границами повторного ASR и неподтверждённым говорящим. Ни отрицания, ни имена, ни утверждения не исправляются по письменному эталону или предполагаемому смыслу эксперимента.

После проверки целая версия `reviewed/` подключается как `outputs/audio`, предыдущая версия сохраняется в `outputs/audio-archive/`. `revision.json` содержит контрольные суммы текущих стенограмм; `promotion.json` связывает текущую и прежнюю версии. Старая проверка содержательных кандидатов архивируется вместе со снимком таблицы, к которой относились её идентификаторы. При наличии `promotion.json` скрипт сравнения автоматически берёт архив предыдущей версии.

`scripts/assemble_audio_analysis.py` пересчитывает кластеры спикеров и пары вопросов/ответов по новым границам. Не зависящие от ASR акустические окна и VAD могут быть перенесены с той же записи и совпадающей длительности; происхождение записано в JSON. При отсутствии предыдущих признаков они вычисляются заново. Восстановленные и перенесённые реплики не получают подтверждённых ролей. Статистика первоначальной кластеризации относится к её входным репликам; количество окончательных неопределённых реплик нужно считать по итоговым сегментам.

`tests/test_audio_review.py` проверяет сохранность исходного ASR, отказ при несовпадении хешей исходника или свидетельств и отсутствие автоматического подтверждения прослушивания. Итоговый аудит запускается с явным ожидаемым числом записей: `python scripts/audit_audio.py --output outputs/audio --expected-recordings 9`.
