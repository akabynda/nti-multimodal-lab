# BioRadio: формат и обработка

## Данные

Девять BCRX записаны BioCapture 5.5.640.20752:

| Записи | Каналы | Частота |
|---|---|---|
| Первые восемь | ECG, RIP, GSR | 1000 Гц |
| Девятая | ECG, RIP, GSR, Flow Rate Sensor 1, Heart Rate PulseOx1, PPG PulseOx1, SpO2 PulseOx1 | 250 Гц |

Частоты, единицы и порядок каналов читаются из заголовка. ECG/RIP хранятся в вольтах и отображаются в мВ; GSR — в мкСм. Частота хранения PPG — 250 Гц, наблюдаемая частота изменения значений — 74.65/с.

`Session1.bcsx` содержит XML настроек. `EventList` всех BCRX пуст; `EventMarkerSettings` задаёт клавишу события. `RecordingStartTime` содержит смещение `+03:00`. Привязка к видео задаётся [отдельно](methodology.md#синхронизация).

## Чтение BCRX

Структура проверена на файлах текущего набора:

1. Открыть ZIP-контейнер, прочитать `header.xml` и `{channel}_{chunk}.rec`.
2. Получить порядок каналов из `SessionInfo/CustomSignalDefinitions`.
3. Отсортировать чанки численно; распаковать каждый `.rec` через raw DEFLATE (`wbits=-15`).
4. Прочитать отсчёты как little-endian float32 (`<f4`). Полный чанк — 120 с: 120000 отсчётов при 1000 Гц или 30000 при 250 Гц.
5. Рассчитать длительность: `RecordingLengthTicks / 10^7`.

Парсер проверяет версию заголовка, непрерывность индексов, DEFLATE, кратность длины четырём байтам и число отсчётов с допуском 8. Избыток обрезается до общей длительности; NaN сохраняются на исходных позициях. Метаданные содержат SHA-256 источника и счётчики пропусков.

## Методы

### ЭКГ и RR

- Butterworth 5–25 Гц, порядок 3, SOS, фильтрация вперёд и назад на исходной частоте.
- Квадрат амплитуды усредняется за 60 мс. Порог — 25% от 95-го перцентиля энергии; локальные блоки обновляются каждые 30 с с контекстом.
- Минимальное расстояние между пиками — 300 мс. Уточнение по экстремуму QRS в ±90 мс с учётом полярности.
- Пропуски интерполируются для фильтрации; пики в пределах 250 мс от пропуска исключаются. В выходных трассах пропуски восстанавливаются.
- RR вне 300–2000 мс или с отклонением >20% от медианы 11 интервалов отвергаются. Исходные интервалы и флаги сохраняются.
- RMSSD и pNN50 используют соседние принятые интервалы без соединения через отвергнутые.

### ВСР

Окно 120 с, шаг 5 с. Признаки: средний RR, ЧСС, SDNN с выборочным SD, RMSSD, pNN50, коэффициент вариации RR.

Спектр: интерполяция принятых RR на 4 Гц, удаление линейного тренда, Welch с одним сегментом Hann на всё окно без нулевого дополнения. Разрешение около 0.0084 Гц.

| Поле | Диапазон / единицы |
|---|---|
| VLF | 0.0033–0.04 Гц, мс² |
| LF | 0.04–0.15 Гц, мс² |
| HF | 0.15–0.4 Гц, мс² |
| Общая мощность | VLF + LF + HF, мс² |
| PSD | мс²/Гц |
| LF/HF | Безразмерное отношение |
| `ulf_ms2` | `null`: не рассчитывается на 120 с |

VLF и общая мощность имеют исследовательский статус. Окна перекрываются.

Спектр рассчитывается при ≥30 принятых RR, покрытии ≥90%, доле отвергнутых ≤20% и разрывах ≤5 с.

`ecg_quality=usable_automatic` требует: отвергнуто ≤10% RR, разрывы ≤3 с, покрытие ≥90%, размах QRS ≥0.05 мВ, нечисловых отсчётов <1%, отсчётов на пределе АЦП <0.1%.

### Дыхание

RIP ресэмплируется до 25 Гц с anti-alias фильтрацией, затем фильтруется в полосе 0.08–0.7 Гц. Доминирующая частота записывается в `resp_candidate_bpm`. `resp_bpm` заполняется при доле мощности в ±0.04 Гц от максимума ≥35% и автокорреляции на его периоде ≥0.25.

EDR рассчитывается из модуляции амплитуды QRS на сетке 4 Гц.

### Контактный ФПГ

`detect_ppg_peaks`: фильтр 0.5–5 Гц, расстояние между пиками ≥300 мс, prominence 25% от медианы локального двухсекундного масштаба.

`analyze_ppg` возвращает пульсовые интервалы, оконные признаки PRV и дыхательную модуляцию амплитуды. Для сравнения с ЭКГ используются окна с ≤10% отвергнутых интервалов, покрытием ≥90%, разрывами ≤3 с и ≥99% конечных значений. ЭКГ и контактный ФПГ используют общие часы BioRadio.

### GSR

Сохраняется сырой сигнал с флагами качества: постоянные участки и значения вне диапазона. В наборе встречается значение 100000 при заданном максимуме 24000; в девятой записи оно занимает >99.99% отсчётов.

## Запуск и API

Все BCRX в каталоге данных:

```powershell
python scripts/analyze_bio.py --data ..
```

Отдельная запись:

```powershell
python scripts/analyze_bio.py --input ../session.bcrx --subject-id Participant09
```

Полные результаты с неизменившимся SHA-256 пропускаются. `--force` запускает пересчёт, `--output` задаёт каталог результатов. Общая сводка объединяет все сохранённые записи.

```python
from nti_lab.biosignals import read_bcrx, analyze_recording

rec = read_bcrx("participant.bcrx")
ecg = rec.channels["ECG"]        # вольты
fs = rec.sample_rates["ECG"]     # Гц
metadata = analyze_recording("participant.bcrx", "outputs/bio")
```

`rr_spectrum(rr_t_s, rr_ms, rr_valid, start_s, end_s)` возвращает `frequency_hz`, `power_ms2_hz` и `status`.

## Выходные файлы

В `outputs/bio/<subject>/`:

| Файл | Содержание |
|---|---|
| `metadata.json` | Источник, хеш, каналы, частоты, длительность, качество |
| `metrics.csv` | Оконные признаки; `center_s` — середина окна |
| `rr_intervals.csv` | `time_s` — середина интервала, `rr_ms`, `accepted` |
| `signals.npz` | Сигналы, пики и интервалы |
| `timeseries.json` | Обзорные трассы: ECG min/max за 0.1 с, RIP/GSR 5 Гц, RR по событиям, EDR 4 Гц |
| `quality_audit.png` | Фрагмент ECG, RR, ЧСС и RIP |
| `ppg_metrics.csv`, `ppg_intervals.csv` | PRV и пульсовые интервалы при наличии PPG |
| `ecg_ppg_comparison.csv`, `.png` | Сравнение ЭКГ и контактного PPG |

Массивы `signals.npz`:

- ECG 250 Гц: `ecg_t_s`, `ecg_mv`, `ecg_filtered_mv`; пики и RR: `r_peaks_s`, `rr_t_s`, `rr_ms`, `rr_valid`.
- RIP 25 Гц: `rip_t_s`, `rip_mv`, `respiration_mv`; EDR 4 Гц: `edr_t_s`, `edr_mv`.
- GSR 5 Гц: `gsr_t_s`, `gsr_us`.
- PPG: `ppg_t_s`, `ppg_raw`, `ppg_filtered`, `ppg_peaks_s`, `ppg_interval_t_s`, `ppg_interval_ms`, `ppg_interval_valid`.

Для PPG метаданные содержат `ppg_analysis` и `ecg_ppg_comparison`; `timeseries.json` — объект `ppg` с `available`, `t_s/raw/filtered`, частотой и интервалами.

Общий каталог содержит `summary.json`, `windows.csv`, `aggregate_summary.csv`, `aggregate_summary.png` и `.svg`. Графики используют обозначения P01–P09; сопоставление с исходными файлами хранится в локальном CSV.
