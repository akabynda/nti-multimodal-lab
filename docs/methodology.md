# Методы обработки

## Сопоставление историй и стенограмм

Вход: шесть письменных историй на участника и его ASR-стенограмма. Текущий набор содержит 54 истории и девять участников. Подготовка источников описана в [схеме данных](../data/README.md).

1. Построить окна стенограммы длиной 45 с с шагом 10 с; исключить окна с менее чем пятью словами.
2. Использовать слова по середине временной метки. При отсутствующем или устаревшем пословном выравнивании использовать целые сегменты с актуальным текстом.
3. Привести текст к нижнему регистру, заменить «ё» на «е», сократить повторные пробелы.
4. Построить TF-IDF на 54 эталонах: символьные n-граммы внутри слов, длина 3–5, логарифмирование частоты.
5. Рассчитать косинусное сходство каждого окна с шестью историями участника.

`story_matches.csv` содержит лучшее окно каждой истории. `window_matches.csv` — первую и вторую темы окна и разность сходств. Поиск сохраняет `review_required=true` и пустую `truth_label`.

## Содержательная сверка

`content_comparison.json` и CSV содержат цитаты эталона и ASR, временной интервал и категорию:

| Категория | Значение |
|---|---|
| `consistent` | Соответствие эталону |
| `different` | Дополнительные сведения вне проверяемого факта |
| `omitted` | Отсутствие эпизода |
| `uncertain` | Неопределённость ASR |
| `contradiction_candidate` | Замена события, примера или существенной детали эталона |

Цитаты проверяются на наличие в источнике и указанном интервале стенограммы. Контекст включает 10 с до и 5 с после интервала с пересекающимися сегментами. Сводка сохраняется в `content_comparison_report.json`.

Текущая сверка выполнена ассистентом по тексту; `audio_verified=false`. Роли говорящих назначены редакторски по диалогу. Экспертные метки отдельных ответов по экспериментальному протоколу отсутствуют.

```powershell
python scripts/analyze_research.py --audio-dir outputs/audio --notes data/private/comparison_notes_large_v3.json
```

`--notes` задаёт полный набор сверки. При наличии `data/private/comparison_notes_large_v3.json` обычный запуск выбирает его автоматически. `revision_provenance` сохраняет хеши предыдущей таблицы, заметок и стенограмм.

## Видео

`vision.py` использует MediaPipe Pose для области головы и точек тела, Face Landmarker — для лба и щёк. Метод POS рассчитывает rPPG по цветовым трассам. По видимым точкам рассчитывается двумерная кинематика. Спектральные оценки пульса и дыхательных движений сохраняются с показателями качества. Скрытые точки и отсутствующие измерения сохраняются как пропуски. В наборе один видеоракурс.

## Синхронизация

```powershell
python scripts/estimate_sync.py
```

Параметры: `--recording ID` — одна запись, `--audio DIR` — каталог стенограмм, `--force` — повторный расчёт существующих кандидатов.

БиоРадио запускается раньше видео и заканчивается позже. Диапазон опережения: `0 ≤ lead_s ≤ bio_duration − video_duration`. Преобразование времени: `video_time = bio_time − lead_s`.

1. Выделить начальный и конечный спокойные участки по инструкциям закрыть глаза в ASR; использовать раскрытие глаз как дополнительный признак.
2. Преобразовать R-пики ЭКГ в сглаженные импульсы; отфильтровать их и rPPG в полосе 0.65–3 Гц.
3. Сопоставить абсолютные корреляции, конкурирующие максимумы и оценки двух участков.

Ноль медиа — первый декодированный кадр и аудиофрейм. Масштаб времени равен 1. Для анализа чувствительности задержка пульсовой волны задаётся диапазоном 0.08–0.45 с; сохранённый диапазон смещения — диапазон чувствительности.

`supported_unverified` — согласованный кандидат, `ambiguous_unverified` — неоднозначный кандидат. Ручная проверка задаётся отдельно. `sync.py` строит часы `offset_s + scale × source_time` по опорным меткам.

Выход в `outputs/sync/`: JSON записей с путём и хешем ASR, `summary.csv`, `comparisons.csv`, `aggregate_summary.png`.

## Анализ условий truth/lie

Входные файлы в `data/private/`:

- `reviewed_trials.csv`: `participant_id`, `recording_id`, `start_s`, `end_s`, `condition`, `label_source`, `reviewed`. Условия: `truth`, `lie`; `baseline` хранится отдельно.
- `labelled_features.csv`: признаки размеченных ответов.
- `research_features.json`: список анализируемых признаков.

Классический темперамент задаётся значением `choleric`, `sanguine`, `phlegmatic` или `melancholic` и полем `temperament_source`, одним на участника. Категории XLSX «Содействующий», «Контролирующий», «Координирующий», «Стимулирующий» сохраняются в исходной шкале. Классический темперамент для девяти участников не задан.

| Расчёт | Метод и параметры |
|---|---|
| Контраст условий | Среднее по качественным ответам внутри участника; `lie − truth` |
| Сравнение четырёх темпераментов | Перестановочный F-тест, 4999 перестановок, seed 42; минимум 3 участника с обоими условиями в каждой группе |
| Выход группового сравнения | Число пар, средний контраст, 95% процентильный bootstrap по участникам (2000 повторов), F, η², p, поправка Холма по признакам |
| Модель условий | Логистическая регрессия, `C=1`, балансировка классов, порог `0.5`; сравнение без темперамента и с one-hot-кодированием |
| Разделение модели | Leave-one-participant-out; импутация медианой, индикаторы пропусков, масштабирование и кодирование на обучающей части |
| Требования модели | Минимум 5 участников, оба класса в наборе и в каждой обучающей части |
| Метрики модели | Balanced accuracy, F1, ROC AUC; одинаковый суммарный вес участников |

Запуск: `python scripts/analyze_research.py`. При отсутствии входной разметки `hypotheses.json` и `validation.json` сохраняют статус `blocked` с причиной. Совместный анализ анкет и меток соответствия описан [отдельно](multimodal_analysis.md).
