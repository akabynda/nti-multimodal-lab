# Исходные данные

Проект ожидает папку, указанную в `NTI_DATA_ROOT` (по умолчанию родительская папка проекта):

```text
dataset/
  Participant01.bcrx
  Session1.bcsx
  Результаты.xlsx
  1_30/
    00001_Participant01.MTS
  nti-lab/
```

Идентификатор участника после первого подчёркивания в видео связывается с каталогом `outputs/bio/<participant_id>`. Обычно он совпадает с именем BCRX. Для произвольного имени исходника задайте ID явно:

```powershell
.\.venv\Scripts\python.exe scripts/analyze_bio.py --input data/private/Participant09/recording.bcrx --subject-id Participant09
```

Повторный запуск сохраняет полные результаты неизменившихся записей и обновляет общую сводку. Видео может быть MTS или MP4; синхронизация использует фактический `source_path`/`source_file`. Совпадение ID связывает источники, а временное смещение рассчитывается отдельно.

В подготовленном наборе восемь BCRX содержат ECG/RIP/GSR по 1000 Гц; девятый — семь каналов по 250 Гц, включая контактный PPG, пульсоксиметрические ЧСС/SpO2 и датчик потока. Частоты и порядок каналов читаются из заголовка. Для контактного PPG сохранены PRV, качество окон и сравнение с ECG на общей шкале БиоРадио. Полный перечень исходных каналов остаётся в `metadata.json`; оригинальные BCRX сохраняются.

Письменные истории и подтверждение их истинности хранятся локально в `data/private/stories.json`; исходные документы, ссылки, хеши, сопоставления профилей и ручные метки также остаются в `private/`. В поставленном локальном наборе они уже подготовлены из материалов владельца.

Для другого исследования заполните такую же схему на данных, которые разрешено обрабатывать. Не загружайте исходные записи людей в публичный репозиторий. Пример единичной истории:

```json
{
  "stories": [{
    "story_id": "Participant01_story_01",
    "participant_id": "Participant01",
    "title": "Тема",
    "text": "Подтверждённый исходный рассказ",
    "source_url": null,
    "declared_truth_label": "truth",
    "label_provenance": "явное подтверждение автора набора"
  }]
}
```
